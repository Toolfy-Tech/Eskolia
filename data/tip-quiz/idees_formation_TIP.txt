
=============================================================
   IDÉES EN VRAC — PARCOURS FORMATION TIP (E-LEARNING IA)
=============================================================

-------------------------------------------------------------
CONTEXTE
-------------------------------------------------------------
- Application web d'e-learning faite avec IA pour TIP
  (Technicien Informatique de Proximité)
- Pas de QCM (trop complexe à cause des distracteurs)
- Principe de CARDS avec correction immédiate (solo)
  ou différée (multijoueurs)
- Objectif : ludique + pédagogique + proche du terrain

-------------------------------------------------------------
PROFIL TYPE DE L'ÉTUDIANT TIP
-------------------------------------------------------------
- Souvent en reconversion ou sortie de lycée
- Apprend mieux en faisant qu'en lisant
- Attention limitée sur du contenu théorique pur
- Motivation forte si lien direct avec le terrain
- Peur de "mal répondre" devant les autres
- Très à l'aise avec les interfaces numériques
- Besoin de voir sa progression concrètement

-------------------------------------------------------------
LES 4 GRANDS BESOINS PÉDAGOGIQUES
-------------------------------------------------------------
1. Mémoriser des informations techniques denses
   → Commandes, protocoles, codes d'erreur,
     raccourcis, acronymes, ports réseau...
   → Beaucoup de données à ancrer durablement
   → Risque d'oubli rapide sans révision espacée

2. Développer un raisonnement de dépannage
   → Face à un problème inconnu, savoir par où commencer
   → Éliminer les hypothèses une par une
   → Ne pas paniquer devant l'utilisateur

3. Acquérir des réflexes procéduraux
   → Certaines actions doivent devenir automatiques
   → Intégration AD, config IP, jonction domaine...
   → Checklist mentale sans avoir à chercher

4. Communiquer avec l'utilisateur
   → Reformuler un problème technique simplement
   → Rassurer, expliquer, vulgariser
   → Rédiger un ticket ou un compte-rendu

-------------------------------------------------------------
TECHNIQUE 1 — FLASHCARD CLASSIQUE ENRICHIE
-------------------------------------------------------------
Besoin couvert : Mémorisation

Principe :
- RECTO → Question ou terme technique
- VERSO → Réponse + contexte + exemple concret

Ce qu'on ajoute pour la rendre vivante :
- Une icône visuelle par catégorie
- Un niveau de difficulté visible (1 à 3 étoiles)
- Un petit encadré "Astuce terrain" au verso
- Un indicateur "Revu X fois"

Exemple de card :
  RECTO → Quel port utilise le protocole RDP ?
  VERSO → Port 3389 (TCP)
          Astuce terrain : Si tu ne peux pas prendre
          la main à distance, vérifie ce port en premier
          dans le pare-feu Windows.

Correction :
- Solo  → Immédiate au retournement
- Multi → Chacun répond, correction collective après

-------------------------------------------------------------
TECHNIQUE 2 — CARD SCÉNARIO / TICKET
-------------------------------------------------------------
Besoin couvert : Raisonnement de dépannage

Principe :
- On plonge l'étudiant dans une situation réelle
- Il décrit sa démarche de dépannage librement
- La correction affiche la procédure recommandée
  étape par étape
- Il s'auto-évalue : "Est-ce que j'avais le bon réflexe ?"

Exemple de card :
  RECTO →
    TICKET #047
    Un utilisateur appelle. Son PC ne trouve pas le réseau.
    Il est configuré en DHCP.
    Quelle est votre première action ?

  VERSO →
    1. Vérifier les voyants du câble réseau
    2. ipconfig /release puis ipconfig /renew
    3. Vérifier la connectivité avec ping 8.8.8.8
    4. Vérifier le serveur DHCP si plusieurs postes touchés

Correction :
- Solo  → Immédiate avec procédure complète
- Multi → Différée, chaque étudiant partage sa démarche,
          le formateur valide ou débat en groupe

-------------------------------------------------------------
TECHNIQUE 3 — CARD SÉQUENCE / PROCÉDURE
-------------------------------------------------------------
Besoin couvert : Réflexes procéduraux

Principe :
- Une procédure technique est présentée dans le désordre
- L'étudiant remet les étapes dans le bon ordre
- La correction affiche la séquence correcte avec
  explication de chaque étape

Exemple de card :
  RECTO →
    Remets dans l'ordre les étapes pour
    intégrer un PC au domaine Active Directory :
    A. Redémarrer le poste
    B. Vérifier la connectivité réseau
    C. Renseigner le nom du domaine
    D. Entrer les credentials admin du domaine
    E. Aller dans Propriétés Système > Nom de l'ordinateur

  VERSO →
    Ordre correct : B → E → C → D → A
    Explication de chaque étape...

Correction :
- Solo  → Immédiate avec code couleur (vert/rouge par étape)
- Multi → Compétition par équipe, score selon nombre
          d'étapes bien placées

-------------------------------------------------------------
TECHNIQUE 4 — CARD DIAGNOSTIC PAR INDICES
-------------------------------------------------------------
Besoin couvert : Raisonnement de dépannage

Principe :
- Un problème est présenté sans solution
- Les indices sont révélés un par un
- Plus on utilise d'indices, moins on gagne de points
- L'étudiant doit trouver le diagnostic final

Exemple de card :
  RECTO →
    Indice 1 : Le PC démarre mais l'écran reste noir
    [Demander l'indice suivant ?]
    Indice 2 : Le ventilateur tourne normalement
    Indice 3 : Un bip long est émis au démarrage
    → Quel est le diagnostic ?

  VERSO →
    Problème RAM : mauvais contact ou module défectueux
    Solution : Retirer et réinsérer les barrettes,
               tester une par une si plusieurs modules

Correction :
- Solo  → Score décroissant selon indices utilisés
- Multi → Simultané, premier à trouver avec le moins
          d'indices gagne le maximum de points

-------------------------------------------------------------
TECHNIQUE 5 — CARD REFORMULATION
-------------------------------------------------------------
Besoin couvert : Communication avec l'utilisateur

Principe :
- Une explication technique est donnée
- L'étudiant doit la reformuler pour un utilisateur
  non-technicien
- La correction propose plusieurs formulations adaptées

Exemple de card :
  RECTO →
    Explique à un utilisateur non-technicien
    pourquoi son PC rame depuis qu'il a branché
    une clé USB :
    (Contexte technique : la clé est infectée,
    un processus malveillant consomme le CPU)

  VERSO →
    Bonne formulation :
    "Votre clé USB contient un programme indésirable
    qui sollicite trop votre ordinateur. Je vais
    la déconnecter et nettoyer votre PC. Évitez
    d'utiliser cette clé sur d'autres postes."

Correction :
- Solo  → Auto-évaluation avec grille de critères
- Multi → Vote collectif sur la meilleure reformulation

-------------------------------------------------------------
TECHNIQUE 6 — CARD VRAI / FAUX ARGUMENTÉ
-------------------------------------------------------------
Besoin couvert : Consolidation des connaissances

Principe :
- Une affirmation technique est présentée
- L'étudiant dit Vrai ou Faux ET doit justifier
- La justification est obligatoire pour valider la réponse

Exemple de card :
  RECTO →
    VRAI ou FAUX ?
    "Un switch fonctionne au niveau 3 du modèle OSI"
    → Justifiez votre réponse

  VERSO →
    FAUX
    Un switch standard fonctionne au niveau 2 (liaison de données).
    Il utilise les adresses MAC pour commuter les trames.
    Seul un switch de niveau 3 (L3) peut router des paquets IP.

Correction :
- Solo  → Immédiate avec explication complète
- Multi → Bonus de points si la justification est correcte
          même si la réponse Vrai/Faux est bonne

-------------------------------------------------------------
TECHNIQUE 7 — CARD SCHÉMA À COMPLÉTER
-------------------------------------------------------------
Besoin couvert : Architecture réseau et matériel

Principe :
- Un schéma réseau ou matériel est affiché
  avec des éléments numérotés non légendés
- L'étudiant identifie chaque élément
- La correction affiche le schéma légendé complet

Exemple de card :
  RECTO →
    Schéma réseau simplifié
    Identifiez les éléments 1 à 5 :
    1. ___  2. ___  3. ___  4. ___  5. ___

  VERSO →
    1. Box opérateur / Modem
    2. Routeur / Pare-feu
    3. Switch de distribution
    4. Serveur (AD/DHCP/DNS)
    5. Poste client

Correction :
- Solo  → Immédiate élément par élément
- Multi → Score selon nombre de bonnes réponses

-------------------------------------------------------------
TECHNIQUE 8 — CARD ACRONYME / DÉFINITION
-------------------------------------------------------------
Besoin couvert : Vocabulaire et culture technique

Principe :
- Deux sens de jeu possibles :
  → Acronyme → Développé + définition
  → Définition → Trouver l'acronyme

Exemple de card :
  RECTO → Que signifie DNS ? Quel est son rôle ?

  VERSO →
    Domain Name System
    Rôle : Traduit un nom de domaine en adresse IP
    Analogie : C'est l'annuaire téléphonique d'internet
    Commandes utiles :
    → nslookup pour interroger le DNS
    → ipconfig /flushdns pour vider le cache

Correction :
- Solo  → Immédiate au retournement
- Multi → Collective, le premier correct gagne les points

-------------------------------------------------------------
STRUCTURE DES DECKS SUGGÉRÉS POUR TIP
-------------------------------------------------------------
RÉSEAU
  → Commandes réseau (ipconfig, ping, tracert, nslookup...)
  → Protocoles (DHCP, DNS, TCP/IP, RDP, SSH, FTP...)
  → Ports importants (80, 443, 3389, 22, 21, 25...)
  → Schémas d'architecture
  → Dépannage réseau

WINDOWS CLIENT
  → Commandes CMD et PowerShell
  → Gestion des comptes utilisateurs
  → Registre Windows et GPO
  → Codes d'erreur BSOD
  → Raccourcis clavier utiles

WINDOWS SERVER / ACTIVE DIRECTORY
  → Concepts Active Directory (OU, GPO, FSMO...)
  → Gestion DNS et DHCP côté serveur
  → Procédures d'intégration au domaine
  → Droits et permissions NTFS

MATÉRIEL ET PÉRIPHÉRIQUES
  → Composants PC (RAM, CPU, GPU, stockage...)
  → Connectiques (USB, HDMI, RJ45, SFP...)
  → Codes bip POST
  → Dépannage hardware

SÉCURITÉ
  → Bonnes pratiques utilisateur
  → Types d'attaques (phishing, ransomware, MITM...)
  → Outils de protection (antivirus, firewall, MFA...)
  → Gestion des mises à jour

RELATION CLIENT
  → Qualification de ticket
  → Communication avec un utilisateur non-technicien
  → Gestion d'un utilisateur stressé ou mécontent
  → Rédaction de compte-rendu d'intervention

-------------------------------------------------------------
POINTS FORTS DU SYSTÈME
-------------------------------------------------------------
- Pas de QCM → vrai rappel mémoriel, pas de chance
- Correction immédiate en solo = autonomie totale
- Correction différée en multi = interaction réelle
- Progressif : du plus simple (flashcard)
             au plus complexe (scénario, diagnostic)
- Terrain-centré : tout parle du métier réel TIP
- Extensible : on ajoute des cards sans changer
               la mécanique
- Format card universel : toutes les techniques
  rentrent dans le même format
